# IronMan 系统配置页设计

## 目标

在 `/system/configuration` 提供 Batman 系统配置页的核心能力，并以 IronMan 的暗色工作台视觉呈现。页面不使用顶部标题栏或页签工具栏，而是在主工作区内部提供局部导航和紧凑的配置操作区。

## 页面结构

采用工作台式分区：左侧为本页配置导航，右侧为当前配置组内容。配置组包括：

- 数据与备份：导出当前账户的 JSON 数据；选择 JSON 文件并确认导入，导入仅替换当前账户数据。
- 行情与日历：配置首选/备用行情源；在年度日历中编辑交易日和非交易日；刷新当前账户自选与持仓所引用标的的行情缓存。
- AI 服务：维护多个模型配置，支持本地、DeepSeek、Ollama 与 OpenAI 兼容服务；可启用、设置默认模型、编辑连接地址、模型名与 API Key。
- 维护：管理员可清除共享行情缓存；普通用户不显示此操作。

所有操作行保持单行信息、说明文本与命令按钮，不以层层嵌套卡片组织页面。

## 后端与数据边界

- 数据导入/导出沿用 `BackupService`，按当前认证用户隔离。
- 行情源沿用 `MarketService` 的用户配置；页面显示腾讯财经、东方财富和本地模拟源的首选/备用组合。
- 交易日设置升级为年度日历模型，返回计算后的交易日集及保存的覆盖项。历史只有 `nonTradingDays` 的用户设置兼容读取，并视为关闭覆盖项。
- “刷新数据”不会引入全市场标的爬取。它只收集当前账户自选与持仓的去重标的，按该账户的数据源组合强制刷新日线缓存，并返回成功/失败数量。
- AI 模型配置保存为当前用户设置。旧的单一 `ai.config` 兼容迁移为一条模型配置；API Key 只在保存时接收，读取时仅返回是否已配置。
- 共享 `market_bars` 缓存只能由管理员清除。清除操作写入审计日志，普通用户调用返回 403。

## 前端交互

- 配置项在同一页面切换，不改变路由。
- 导出会下载 `ironman-export-YYYYMMDD.json`；导入前读取并校验 JSON，再显示“会替换当前账户数据”的确认对话框。
- 行情源与 AI 模型编辑使用对话框，交易日使用大尺寸年度日历对话框；保存失败保留编辑内容并显示错误。
- 行情刷新、导入、缓存清理均使用按钮 loading 状态和完成结果提示。
- 维护区仅在当前用户 `role === 'admin'` 时渲染。

## 验证

- 后端测试：用户配置隔离；日历覆盖读写；刷新仅访问所属账户标的；非管理员无法清空行情缓存；管理员清空后缓存记录为零。
- 前端测试：路由改为真实系统配置页；导入导出、配置保存和管理员维护操作走对应 API。
- 工程验证：后端测试与 lint、前端 lint/build、`git diff --check`。
