# 持仓诊断公告与财经新闻正文采集方案

## 背景与目标

当前持仓诊断的外部资料主要是网页入口和页面元信息，不能支撑对具体公告、财报和财经新闻的事实分析。本方案将资料链路调整为：本地行情优先、官方披露正文优先、结构化财经新闻补充，并让每个标的的正文和来源摘要都可追溯。

本方案不改变现有的逐标的后台处理方式。每个标的独立获取资料、调用一次 AI、保存结果；单个标的资料源失败不影响其他标的。

## 设计原则

- **来源分层**：官方披露是一级证据，授权或结构化新闻是二级证据，聚合资讯和讨论内容只能作为辅助线索。
- **行情本地优先**：优先复用 `MarketService` 的本地缓存、主行情源、备用行情源和已保存的 K 线，不因新闻采集重新请求行情。
- **正文优先**：外部来源必须尽可能获取实际公告、财报或新闻正文；网页标题、`description` 和入口说明不能作为事实摘要的替代品。
- **可核验**：每条事实保留来源名称、标题、发布时间、原始链接和来源 ID，AI 的结论必须能够回指来源。
- **受控采集**：不开放任意 URL 抓取。来源通过后端适配器注册，适配器独立管理域名、查询参数、正文解析、超时、大小限制和限流。
- **最小持久化**：正文只在生成任务期间暂存，不写入数据库；报告只保存摘要、关键事实、来源元数据和正文哈希。

## 采集流程

对每个持仓标的按以下顺序处理：

1. 从本地 `MarketService` 读取行情和数据时间，生成本地指标证据。
2. 根据交易所和标的代码选择公告适配器，查询最近配置窗口内的公告列表。
3. 从公告列表中筛选与投资者决策相关的类型：定期报告、业绩预告、业绩快报、分红、回购、增减持、股权融资、重大合同、诉讼仲裁、风险提示、停复牌和监管问询等。
4. 查询结构化新闻源，按代码、简称和证券全称匹配，限制时间窗口、来源数量和单篇正文大小。
5. 按 `source + externalId`、规范化标题和正文哈希去重；同一事件优先保留官方披露，新闻只作为补充。
6. 下载正文或附件，在内存中提取纯文本，清除导航、页眉页脚、广告、脚本和重复内容。
7. 对正文做长度截断和结构化预处理，形成当前标的的资料包，再交给该标的的 AI 请求。
8. 保存来源元数据、摘要和关键事实，释放正文暂存内容，继续下一个标的。

默认窗口建议为最近 30 个自然日；定期报告和尚未完成核验的重大事项可扩展到最近 90 天。每个标的默认最多保留 5 条公告和 5 条新闻，实际数量受配置和资料源限制共同约束。

## 正文处理与安全边界

每个来源适配器返回统一结构：

```typescript
interface HoldingDiagnosisSourceDocument {
  sourceId: string;
  sourceName: string;
  type: "disclosure" | "news" | "reference";
  externalId: string;
  title: string;
  publishedAt: string | null;
  url: string;
  content: string;
  contentHash: string;
  availability: "available" | "stale" | "failed";
  origin: "official" | "licensed" | "aggregated" | "discussion";
}
```

适配器必须执行以下限制：

- 只允许注册来源的固定域名和路径模板，禁止使用用户输入拼接任意抓取地址。
- 单次请求设置连接超时、读取超时、响应大小和正文页数上限。
- PDF 优先使用文本层提取；扫描件或 OCR 失败时标记为不可核验，不把乱码送入 AI。
- HTML 只保留正文区域，去除脚本、导航、评论、广告和重复段落。
- 不保存外部正文、PDF 二进制、完整 HTML 或临时正文到报告数据库。
- 只向 AI 传递有限正文片段、标题、发布时间、来源和链接；每篇正文片段设置字符上限。
- 记录抓取时间、HTTP 状态、解析状态和正文哈希，便于失败诊断和去重。

## AI 输入与输出

每个标的只发起一个 AI 诊断请求。输入包含：

- 持仓、成本、最新行情和本地指标；
- 3 至 5 条优先级最高的公告正文片段；
- 3 至 5 条去重后的财经新闻片段；
- 每条资料的来源 ID、标题、发布时间、来源级别和原始链接；
- 报告偏好和不确定性要求。

AI 输出继续限制单个标的正文不超过 600 字，并增加来源级结果：

```typescript
interface HoldingDiagnosisSourceInsight {
  sourceId: string;
  summary: string;
  keyFacts: string[];
  marketImpact: "positive" | "negative" | "mixed" | "unclear";
  confidence: "high" | "medium" | "low";
}
```

摘要规则：

- 摘要必须来自实际正文，不得根据标题或网页元信息编造事实。
- 摘要只描述事实，不把 AI 的交易建议混入来源摘要。
- 每条摘要建议不超过 200 字，关键事实不超过 3 条。
- AI 的分析和操作建议必须引用来源 ID；只有聚合或讨论来源时，必须标注“待核验”。
- 官方公告与新闻内容冲突时，报告优先采用官方披露，并说明冲突。
- AI 调用失败时，使用正文截取或规则化本地摘要，状态标记为 `local_excerpt`，不能显示为 AI 摘要。

## 持久化结构

扩展现有来源记录，至少增加：

- `external_id`：来源系统中的公告或新闻 ID；
- `origin`：`official`、`licensed`、`aggregated` 或 `discussion`；
- `content_hash`：正文内容哈希；
- `retrieved_at`：正文获取时间；
- `summary_kind`：`ai`、`local_excerpt` 或 `metadata_only`；
- `source_insight_json`：关键事实、影响方向和置信度。

继续保存来源标题、发布时间、来源名称、链接、可用状态、摘要和关键事实；不保存正文全文。历史报告必须使用当时保存的摘要和来源元数据，不依赖外部站点后续可用性。

## 失败与降级

| 失败 | 处理 |
| --- | --- |
| 官方公告列表不可用 | 保留本地行情，尝试其他官方披露源，报告标记 `partial` |
| 正文下载超时或超过大小限制 | 保存标题、时间、链接和失败原因，不生成事实摘要 |
| PDF 无文本层且 OCR 失败 | 标记为待核验，不把文件内容交给 AI |
| 新闻源无权限或额度不足 | 降级到已配置的备用新闻源，不伪装为完整新闻覆盖 |
| AI 超时、格式错误或不可用 | 当前标的使用本地行情和正文摘录，继续后续标的 |
| 多来源事实冲突 | 保留各来源并提高不确定性，官方披露优先 |

## 前端展示

每个标的的信息来源列表显示真实资料条目，而不是一个泛化来源入口：

- 收起状态：`来源标题: 摘要预览`；
- 展开状态：完整摘要、关键事实、发布时间、来源级别和原始链接；
- 不显示“已获取摘要”等泛化状态文案；
- 对 `metadata_only` 或 `local_excerpt` 明确标记“仅元信息”或“本地摘录”；
- 来源摘要与“诊断”“关键条件”分离，不计入标的正文 600 字限制。

## 实施顺序

1. 扩展来源接口和数据库字段，保留旧来源记录的兼容读取。
2. 接入巨潮资讯、上交所和深交所的公告列表与正文解析，并用固定 fixture 测试。
3. 在本地 AKShare 服务增加个股新闻 typed endpoint；同时预留 Tushare 服务端配置。
4. 改造逐标的模型输入和结构化输出，增加来源摘要与引用 ID。
5. 改造报告详情来源区域和系统配置中的来源目录。
6. 增加正文解析、去重、来源优先级、超时、权限失败、AI 降级和用户隔离测试。
7. 用真实少量标的做人工验收，确认公告事实、新闻时间、行情时间和建议引用一致后再扩大默认来源数量。

## 验收标准

- 每个标的至少能够获取一条真实公告或结构化新闻正文时，AI 输入中包含正文片段而不是网页元信息。
- 报告中的来源摘要可以回指到标题、发布时间和原始链接。
- 官方公告、新闻和本地行情的时间均显示，过期资料会标记状态。
- 单个来源失败不会阻断同一报告的其他来源或其他标的。
- 不写入外部正文、完整 HTML、PDF 文件或 API 密钥。
- 同一标的、同一来源、同一公告不会重复进入 AI 输入。
- AI 失败时仍保留本地诊断，并明确区分 AI 摘要与本地摘录。
