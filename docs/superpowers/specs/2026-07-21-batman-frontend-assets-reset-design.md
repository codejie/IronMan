# Batman 前端重建与资产页面设计

## 目标与边界

前端保留 Bun、Vite、Vue、会话和 API 客户端，重建业务导航、路由、视图和视觉样式，以 `http://localhost:3030/` 为页面与菜单的唯一参考。首批实现“自选列表”和“持仓信息”，不实施数据分析内容。工作区不得显示标题、面包屑或页签工具栏；仅实现桌面端。

## 菜单与路由

左侧菜单严格使用 Batman 文案与层级：

- 自选列表：`/customized/list`
- 持仓信息：`/holding/list`
- 数据分析：趋势计算、AI咨询
- 三方数据：技术数据、资讯链接、大盘云图
- 韭菜笔记：`/notes/leek-notes`
- 系统配置：`/system/configuration`，并保留 `/sytem/configuration` 兼容 Batman 的历史拼写。

首批只有前两项连接真实业务数据。其余菜单和路由使用同一 Batman 壳层与“待后续实现”的空工作区，不复用 IronMan 现有的仪表盘、管理员、自动化和设置菜单。

## 页面与交互

### 自选列表

直接显示“增加自选”“快速查看”“使用历史数据接口”“刷新”与九列行情表：持有、类型、名称/代码、最新价/目标价/差值、昨收/今开、最高价/最低价/差值、涨跌幅/振幅、量比/换手率、操作。添加、目标价、删除和 K 线弹窗沿用 Batman 的操作语义。

### 持仓信息

工作区顶端为 Batman 的资金信息表，随后是“增加持股”“刷新记录”“使用本地数据”、可展开的持股记录表与清仓记录。表格呈现持仓/成本/市值/盈亏的金额和占比、均价与价差、现价日期、日涨跌及昨日差。父记录只提供详情和删除；交易仅在展开的子记录区创建或删除。

## 数据契约

新增 `POST /api/assets/holdings/batman-workspace`，以 `{ refresh }` 返回资金摘要、活动和清仓持仓及 Batman 显示所需的占比和价差字段。它复用用户级数据源配置、缓存和回退策略；行情不可用时保留本地持仓并返回空行情字段。现有 `POST /api/assets/watchlist/workspace` 作为自选数据源，按需要补齐展示字段。所有记录继续按 `user_id` 隔离。

## 验收

- 先编写持仓工作台的金额、占比、价差、缓存回退与跨用户隔离测试。
- 导航测试覆盖 Batman 菜单和路由；自选/持仓测试覆盖加载、空态、弹窗和错误状态。
- 运行 `bun run test`、`bun run lint`、`bun run build`、`git diff --check`，并在桌面浏览器逐项对比 Batman 的两张资产页面。
