# 持仓详情分析页设计

## 目标

将 IronMan `持仓信息` 表格中的 `详情` 操作改为独立持仓分析页，复刻 Batman 持仓详情的业务闭环：展示标的 K 线、持仓数量、均价、市值和盈亏轨迹，并保留完整操作记录。

主列表中的展开箭头继续只负责显示或收起操作明细。名称点击仍打开通用 K 线对话框，和本设计不冲突。

## 路由与交互

- 新增受登录守卫保护的 `#/holding/detail?id=<holdingId>&ids=<holdingId,...>` 路由，页面标题为 `持仓详情`。
- 持股记录与清仓记录的 `详情` 按钮均进入该路由。`ids` 是用户从当前对应列表进入时的有序持仓 ID，用于上一个、下一个导航。
- 页面头部显示标的名称、代码、类型和当前状态，提供 `返回`、`上一个`、`下一个`。首尾记录禁用对应导航按钮。
- 路由参数无效、记录不存在或记录不属于当前用户时，显示页内错误并保留返回入口；不得通过 ID 推断或读取其他用户的持仓。

## 数据契约

新增 `POST /api/assets/holdings/detail/chart`，请求体：

```ts
{ id: string; refresh?: boolean }
```

响应包含：

```ts
{
  holding: HoldingSummary,
  transactions: HoldingOperation[],
  bars: PriceBar[],
  trace: Array<{
    date: string,
    quantity: number,
    netCost: number,
    averageCost: number | null,
    marketValue: number,
    profit: number
  }>,
  macdLines: Record<string, Array<number | null>>
}
```

- 服务端先按 `userId + holdingId` 获取持仓及操作记录，按 `occurredAt` 升序处理。
- 历史行情范围为“最早操作日（没有操作时使用持仓创建日）至当天”与“今天向前至少三个月”两者中更早的起点至当天，端点均包含在内。
- 行情适配层新增按日期区间获取日线的能力。腾讯接口按每批最多 640 根日线反向分页，东方财富按开始/结束日期请求；结果去重、排序并写入现有缓存。某批外部请求失败时，优先返回已缓存的完整可用区间；没有可用行情才返回外部服务错误。
- 对每个交易日，先应用该日所有操作，再以当日收盘价计算轨迹。`buy` 增加数量和净成本，`sell` 减少数量并扣减实际卖出净收入，`interest` 只调整净成本；`marketValue = quantity * close`，`profit = marketValue - netCost`。这与现有持仓工作区的成本/盈亏口径一致。
- 输出不包含 API 密钥、其他用户的交易、设置或缓存来源细节。

## 图表与页面组成

新增 `HoldingDetailView.vue` 和 `HoldingPerformanceChart.vue`：

1. 顶部摘要：名称、代码、类型、状态、现持有、均价、现价、市值、盈亏和盈亏率。
2. 持仓轨迹面板：持有数量柱状图，以及均价、市值、盈亏三条可读曲线；每条价值曲线使用独立尺度，数量使用右侧轴。
3. 行情面板：K 线与已选 MA 线。
4. 副图：沿用共享 K 线组件的 `MACD / 成交量` 选择和本地缓存偏好；MACD 与同一份详情行情一起返回，避免长持仓的指标被截断；所有面板共享日期十字光标。
5. 明细面板：默认展示操作记录；用户可切换到按交易日生成的跟踪记录，字段包含日期、数量、净成本、均价、收盘价、市值和盈亏。

详情页不提供时间段切换，始终完整显示上述区间；MA 与副图选择继续与通用 K 线对话框共用同一 `localStorage` 偏好键。两处控件采用相同的紧凑尺寸。

## 错误与加载状态

- 首次加载显示骨架或简洁加载提示；刷新期间保留上一份有效图表，避免画布闪空。
- 没有操作记录时展示空状态，不生成虚构轨迹。
- 有操作但没有行情时显示操作表和明确的行情错误，不阻塞返回或记录导航。
- 切换上一条/下一条时使用请求序号丢弃过期响应，避免慢请求覆盖新标的。

## 验收与测试

- 后端：用户 A 不能读取用户 B 的详情图；买入、卖出、计息操作能产生正确日度数量、净成本和盈亏；日期区间至少覆盖三个月且包含当天；外部数据源失败时缓存可回退。
- 前端：`详情` 正确生成路由与 `ids`；首尾导航禁用；通用 K 线对话框不受影响；持仓详情渲染轨迹、K 线和操作/跟踪表切换。
- 运行 `bun test`、`bun run lint`、`bun run build`；用真实页面验证一条有多笔操作的持仓和一条清仓记录。
