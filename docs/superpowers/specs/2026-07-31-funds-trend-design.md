# 资金趋势功能设计

> 日期：2026-07-31
>
> 状态：设计已确认，待制定实施计划
>
> 范围：当前 v1.x 工程功能；不纳入已暂时搁置的 v2.0 产品增强方案

## 1. 背景与目标

当前“持仓信息”页面顶部的“资金信息”只展示当前时点的总资产、现金、成本、本金、市值和盈亏，不能回答这些数值在一段时间内如何变化。

本功能增加独立的“资金趋势”页面，按交易日重建并展示最近 3 个月、6 个月或 1 年的资产和盈亏变化。历史结果由资金流水、全部持仓操作和日线行情计算，不新增不可重建的资金事实；计算后的每日结果持久化，后续按需补充，并允许用户在“系统配置 > 数据”中重新计算。

### 目标

- 用图表展示总资产、持仓市值、现金、本金、每日盈亏和累计盈亏的变化；
- 活动持仓和清仓记录采用同一套历史计算口径；
- 默认快速展示最近 3 个月，并支持切换到 6 个月和 1 年；
- 首次计算后复用每日派生结果，只计算缺失日期，减少重复行情读取和计算；
- 历史业务记录发生变化时明确提示数据待更新，由用户统一重新计算；
- 保持现有持仓页面布局和高频操作不受影响。

### 非目标

- 不建设 v2.0 资产快照、账户、组合或收益归因体系；
- 不提供任意日期范围、超过一年的历史或非交易日曲线；
- 不修改资金、持仓和行情事实数据；
- 不在趋势页面提供资金调整、交易或重新计算操作；
- 不自动定时生成每日结果。

## 2. 已确认的产品决策

| 项目 | 决策 |
| --- | --- |
| 页面承载 | 使用独立页面，路由为 `/holding/funds/trend`。 |
| 入口 | 放在持仓页“资金信息”标题右侧，使用 Lucide 图表图标按钮。 |
| 时间范围 | 默认 3 个月，支持 `3个月 / 6个月 / 1年` 分段切换。 |
| 页面布局 | 采用分层分析工作台：指标条、资产变化图、盈亏变化图、每日明细。 |
| 历史生成 | 按交易日、资金流水、当日持有量和当日价格计算。 |
| 结果复用 | 持久化每日派生结果；首次按需生成，切换范围时只补缺失日期。 |
| 重新计算 | 放在“系统配置 > 数据”，重建最近一年，不放在趋势页面。 |

## 3. 页面与交互

### 3.1 持仓页入口

将“资金信息”的纯文本标题改为左右布局：

- 左侧保持“资金信息”；
- 右侧增加 `ChartNoAxesCombined` 图标按钮；
- 使用现有 `batman-icon-button`、`data-hint="查看资金趋势"` 和 `data-hint-position="top"`；
- `aria-label` 为“查看资金趋势”，不使用原生 `title`；
- 点击进入 `/holding/funds/trend`，不增加一级导航或二级菜单。

### 3.2 资金趋势页面

页面从上到下分为以下区域：

1. **标题栏**：返回“持仓信息”、标题“资金趋势”、右侧时间段分段控件。
2. **数据状态**：覆盖日期、最近计算时间，以及“已更新、正在补充、待重新计算、部分数据、计算失败”状态。
3. **指标条**：期末总资产、持仓市值、可用资金、累计盈亏、区间最大回撤。指标采用紧凑条带，不使用大型卡片。
4. **资产变化图**：同一金额坐标展示总资产、市值、现金和本金；资金调整与清仓等关键事件显示标记，悬停查看当日金额和事件。
5. **盈亏变化图**：累计盈亏使用折线，每日盈亏使用正负柱；颜色沿用工程现有的正值红色、负值绿色规则。
6. **每日明细**：默认显示最近 10 个交易日，列为交易日、总资产、市值、现金、本金、当日盈亏、累计盈亏和数据状态；支持分页查看当前时间段。

时间段以最新已完成交易日为结束日，分别向前推 3、6 或 12 个自然月，再取范围内的交易日。当前交易日未形成可靠日线收盘价时不写入历史结果，页面显示截至最近一个完整交易日。

趋势页面不提供“重新计算”按钮。若数据已失效，页面顶部显示“资金历史数据需重新计算”，并提供跳转到“系统配置 > 数据”的文本链接。

### 3.3 系统配置入口

在现有“系统配置 > 数据”标签中增加“资金趋势历史数据”设置行：

- 展示已生成日期范围、交易日数量、最近计算时间、计算版本和当前状态；
- 右侧使用带 `RefreshCw` 图标的“重新计算”按钮；
- 点击后使用工程统一确认对话框，说明会重建最近一年、包含活动持仓和清仓记录，并可能读取历史行情；
- 执行中按钮禁用并显示旋转状态，完成或失败使用统一浮动提示；
- 失败时保留上一版每日结果，并展示可重试状态；
- 不增加“清空历史”功能，避免用户把清空误解为删除资金事实。

## 4. 每日计算口径

### 4.1 日期与处理顺序

- 交易日来自工程现有的用户交易日历；将当前位于 `app.ts` 的日历读取规则抽成可复用的 `TradingCalendarService`，按范围读取涉及的两个自然年度，并继续应用工作日默认值和用户覆盖配置；
- `occurred_at` 按 `Asia/Shanghai` 转换为业务日期，不能直接截取 UTC 日期；
- 每个交易日先应用当日及以前的资金流水和持仓操作，再按当日收盘价计算期末持仓市值；
- 同一日存在多笔操作时按 `occurred_at`、`created_at`、`id` 稳定排序，保证重复计算结果一致。

### 4.2 指标公式

对交易日 `t`：

```text
现金(t)       = 截至 t 的 cash_ledger.amount 累计值
本金(t)       = 截至 t 的 adjustment 类资金流水累计值
持有量(i,t)   = 标的 i 截至 t 的买入量 - 卖出量
市值(t)       = Σ 持有量(i,t) × 有效收盘价(i,t)
总资产(t)     = 现金(t) + 市值(t)
累计盈亏(t)   = 总资产(t) - 本金(t)
累计盈亏率(t) = 本金(t) = 0 时为空，否则累计盈亏(t) / |本金(t)|
当日盈亏(t)   = 总资产(t) - 总资产(t-1) - 当日 adjustment 净额
日收益率(t)   = 上一交易日总资产为 0 时为空，否则当日盈亏(t) / |总资产(t-1)|
业绩指数(t)   = 上一日业绩指数 × (1 + 日收益率(t))，序列首个有效值为 1
```

为计算返回范围第一日的当日盈亏，服务额外计算前一个交易日作为基线，但不将它放入响应。没有可用基线时，第一日当日盈亏、日收益率为空。

区间最大回撤根据剔除外部入金/出金影响的业绩指数动态计算，不能直接对总资产曲线取回撤：

```text
回撤(t) = 业绩指数(t) / 截至 t 的业绩指数峰值 - 1
最大回撤 = min(回撤(t))
```

买入、卖出和费用已经反映在现金与持有量中；分红/计息进入现金但不计为外部本金，因此进入投资盈亏。所有金额在服务层使用统一精度规则计算，响应前再格式化，不在前端重新推导业务指标。

### 4.3 清仓与再次买入

- 计算读取当前用户全部 `holdings` 和 `holding_transactions`，包括 `active` 与 `closed`，禁止只读取活动持仓；
- 清仓日前，该持仓按每日期末数量和价格参与市值；
- 清仓当日应用卖出后，期末数量和市值为 `0`，卖出所得扣除费用后进入现金；
- 已实现盈亏继续体现在总资产和累计盈亏中，不因持仓清仓而从历史曲线消失；
- 同一标的清仓后再次买入可以对应新的 `holding_id`，总资金计算按用户全部交易归并，曲线保持连续；
- 删除持仓或操作前先取得最早受影响业务日期，删除完成后将该日期写入历史失效状态。

### 4.4 缺失行情

- 标的当日停牌或缺少日线时，沿用该标的此前最近一个有效收盘价，并将该日计入 `carriedPriceCount`；
- 为取得范围第一日的沿用价格，每个标的额外查询范围开始日前最近一条有效日线；
- 若标的在持有期间从未取得过价格，该标的当日不计入市值，结果标记为 `partial` 并计入 `missingPriceCount`；
- 图表仍展示可计算部分，但状态栏和每日明细明确显示估值沿用或缺失数量；
- 计算失败不能用 `0` 价格替代缺失价格。

## 5. 持久化与增量策略

每日记录是可重建的派生结果缓存，不是资金和持仓的第二事实源。

### 5.1 数据表

新增迁移版本 11：

#### `fund_daily_metrics`

| 字段 | 说明 |
| --- | --- |
| `user_id + trade_date` | 联合主键；所有查询先按当前用户隔离。 |
| `cash_available`、`principal`、`market_value`、`total_assets` | 当日期末金额。 |
| `external_cash_flow`、`daily_profit`、`daily_return`、`performance_index`、`cumulative_profit`、`cumulative_profit_rate` | 资金流、盈亏与资金流调整后的业绩指标。 |
| `instrument_count`、`priced_count`、`carried_price_count`、`missing_price_count` | 数据质量。 |
| `data_status` | `complete` 或 `partial`。 |
| `calculation_version`、`calculated_at` | 公式版本与生成时间。 |

#### `fund_history_state`

每用户一行，保存 `covered_from`、`covered_to`、`dirty_from`、`status`、`last_error`、`calculation_version` 和 `updated_at`。`status` 使用 `idle | calculating | dirty | failed`。

### 5.2 首次、补充与追加

- 首次进入默认 3 个月时，只生成该范围内尚不存在的交易日；
- 切换到 6 个月或 1 年时，只补充更早的缺失交易日，不改写已生成日期；
- 后续出现新的完整交易日时，从 `covered_to` 之后追加；
- 计算任何片段前，都从全部既有流水和交易重建片段起点的现金与持仓状态，不能假设起点为零；
- 行情优先读取 `market_bars` 缓存，覆盖不足时通过现有 `MarketService` 的范围查询补充；每次最多并发读取 4 个标的，避免压垮数据源；
- 片段计算完成后在一个数据库事务中写入每日结果和覆盖状态。

### 5.3 数据失效

以下写操作成功后调用统一的 `markFundHistoryDirty(userId, affectedDate)`：

- 新增或删除持仓操作；
- 新增资金调整；
- 删除持仓及其全部操作；
- 后续若增加历史记录编辑，也执行同样处理。

`dirty_from` 保存最早受影响日期。存在失效数据时，普通历史查询继续返回上一版可用结果并显示 `dirty`，但不再向后追加，防止基于错误起点产生新记录。行情源切换和缓存刷新不自动改写已经生成的历史；用户可通过重新计算采用最新可用行情。

当应用的 `calculation_version` 高于已有结果时，自动将状态标记为 `dirty`。

### 5.4 重新计算

- 重新计算范围固定为最近一年至最新完整交易日；
- 先在内存中完成资金、持仓和行情归并，只有全部可写结果准备完成后才开启事务替换最近一年结果；
- `partial` 属于成功结果；服务异常或事务失败属于失败，并保留旧结果；
- 成功后清除 `dirty_from`，更新覆盖范围、计算版本和时间；
- 超过一年前且曾按旧规则生成的数据不在本功能界面使用，也不需要保留。

## 6. 后端服务与接口

### 6.1 服务边界

- `FundHistoryService`：读取事实数据、构建交易日序列、计算每日指标、补充范围、重新计算和标记失效；
- `TradingCalendarService`：从用户设置生成指定年份的交易日，供现有设置接口和资金历史共同使用；
- `MarketService`：继续负责日线范围查询和行情缓存，不复制数据源适配逻辑；
- `AssetsService`：在资金或持仓写操作成功后通知 `FundHistoryService` 标记失效，不承担历史计算；
- 路由层只做认证、Zod 校验和响应转换。

### 6.2 OpenAPI

除现有约定允许的特殊场景外继续使用 `POST` 和统一响应结构。

| 接口 | 请求 | 结果 |
| --- | --- | --- |
| `POST /api/assets/funds/history` | `startDate`、`endDate`，跨度不得超过 1 年 | 指标摘要、每日序列、覆盖与数据状态；缺失范围会在返回前按需补充。 |
| `POST /api/assets/funds/history/status` | 空请求体 | 供系统配置读取覆盖范围、交易日数、版本、更新时间和失效/失败状态。 |
| `POST /api/assets/funds/history/recalculate` | 空请求体；确认由前端统一对话框完成 | 重新计算最近一年并返回新状态；同一用户已有计算进行时返回冲突错误。 |

接口不接受 `user_id`，始终使用认证上下文中的用户。日期必须是 `YYYY-MM-DD`，开始日不得晚于结束日，结束日不得超过当前日期。

- `FundsTrendView.vue`：路由页面、时间段状态、接口请求、状态与每日明细；
- `FundsAssetTrendChart.vue`：总资产、市值、现金、本金和事件标记；
- `FundsProfitTrendChart.vue`：累计盈亏线、每日盈亏柱；
- `FundsHistoryStatus.vue`：覆盖、计算时间、完整度和失效状态；
- 在 `HoldingsView.vue` 增加图标入口；
- 在 `SystemConfigurationView.vue` 的数据标签增加历史数据状态与重新计算入口。

图表继续使用工程现有 ECharts 依赖和 `CanvasRenderer`，使用 `ResizeObserver` 响应容器变化。桌面视图保持紧凑全宽；窄屏指标条改为两列，图表保持稳定最小高度，每日明细允许横向滚动，任何文字和控件不得重叠。

## 8. 错误与状态处理

- `loading`：首次或切换范围时显示稳定高度的加载状态；
- `empty`：没有资金流水和持仓操作时提示“暂无可计算的资金历史”，提供返回持仓页入口；
- `partial`：保留图表并提示缺失/沿用行情数量；
- `dirty`：展示旧结果和明显的待更新提示，不静默重算；
- `failed`：若有旧结果则继续展示并提示失败；没有旧结果时显示重试入口；
- `calculating`：禁止同一用户重复请求重新计算；
- 页面反馈使用统一浮动提示或页内状态，不使用浏览器原生 `alert`、`confirm` 或 `prompt`。

## 9. 测试与验收

### 后端

- 只有现金、只有活动持仓、部分卖出、完全清仓、清仓后再次买入和分红/计息；
- 入金与出金不计为当日投资盈亏，买卖费用计入盈亏；
- 非交易日被排除，同日多笔操作结果稳定；
- 停牌沿用前收盘价，无历史价格时标记部分数据；
- 首次 3 个月、扩展 6 个月、扩展 1 年和新交易日追加只写缺失日期；
- 历史写操作正确设置最早 `dirty_from`，失效状态下不继续追加；
- 重新计算成功替换最近一年，行情或事务失败保留旧结果；
- 用户 A 无法读取、重新计算或影响用户 B 的每日结果；
- 日期跨度、非法日期和并发重新计算返回明确错误。

### 前端

- “资金信息”图标具有正确 `aria-label` 和 `data-hint`，点击进入独立页面；
- 默认请求 3 个月，切换 6 个月和 1 年使用正确日期；
- 指标、两类图表和每日表格使用接口值，不在前端重复计算；
- 加载、空态、完整、部分、待更新和失败状态均可见且不改变整体布局；
- 系统配置重新计算使用统一确认框，执行中禁用，成功/失败反馈正确；
- 桌面和移动视口无文字、图例、按钮和图表重叠。

### 验收样例

固定样例包含一次入金、两次买入、一次分红、一次部分卖出、一次完全清仓和清仓后再次买入。按样例逐日手工复算现金、数量、市值、总资产、当日盈亏和累计盈亏，接口结果必须一致；清仓后的历史市值不能消失，清仓所得和已实现盈亏必须继续反映在资金曲线中。
