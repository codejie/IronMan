# 持仓诊断稳定生成流程设计

## 背景与目标

当前持仓诊断把所有活动持仓放入一次 AI 多轮工具调用中。输入过大、工具协议兼容性差、单个标的失败会影响整份报告，最终通常只显示“AI 不可用，已使用本地摘要”。本次调整的目标是让报告稳定地产生逐标的分析，同时保留 AI 失败时的可用本地诊断。

报告仍然只提供条件化决策协助，不执行交易，不承诺收益。公告和财经资讯只有在资料适配器返回可核验摘要、标题和时间时才能作为 AI 事实输入；仅有跳转链接的来源必须明确标记为待核验。

## 方案

### 单标的队列

一次诊断创建一个 run，但后端按 `listEligibleHoldings` 返回的顺序逐个处理标的：

1. 读取该标的的持仓、成本、日线行情和配置的资料源。
2. 计算固定的本地趋势证据，并构造只包含当前标的的紧凑输入包。
3. 对当前标的发起一次 AI 请求，AI处理过程中允许模型调用服务端工具。
4. 校验并规范化当前标的输出，成功则记录 AI 方法；失败、超时或返回格式错误则立即记录本地诊断和具体失败原因。
5. 立刻保存该标的结果并更新 run 进度，然后继续下一个标的。

报告正文由后端根据已完成标的的结果生成，限制在 600 个字符以内。这样 AI 不需要一次生成整份报告，也不会因正文过长而丢弃所有 AI 结果。

### AI 请求协议

每个标的的请求只包含：持仓事实、当前价格和成本、有限窗口的行情数据、本地指标证据、可用的资料摘要和报告偏好。链接型来源，如新闻、公共，尝试读取摘要信息，用于生成报告参考使用。

请求使用独立的结构化输出提示，返回一个标的的分析、建议方向、时机、参考价格、采用操作、失效价格和不确定性。请求体允许携带指向后端服务的 `tools` 或 `tool_choice`，以获取本地标的行情数据、利用本地算法工具、生成图表参数。

已知支持 JSON 模式的服务商可以携带 `response_format`；其他服务商使用普通请求，由服务端解析 JSON 或 JSON 代码块。响应解析失败只影响当前标的，不影响队列。

### 超时、重试和失败分类

单标的 AI 请求使用固定超时。网络错误、429 和 5xx 允许一次短重试；4xx 配置错误、JSON 解析错误和超时不重复消耗请求，直接进行该标的本地降级。错误信息向用户暴露服务类型和 HTTP 状态或错误类别，不暴露 API Key、完整请求地址或原始敏感内容。

失败分类至少包括：

- 未配置远程模型：`local`，说明使用本地诊断；
- 网络或服务不可达：`unavailable`，附检查地址、模型和服务状态的提示；
- 服务超时：`timeout`，附单标的超时秒数；
- 响应格式不正确：`unavailable`，说明模型未按诊断协议返回。

## 持久化与状态

run 在开始后创建可读取的报告骨架。每个标的完成后立即写入 `holding_diagnosis_items` 及其来源记录，并更新报告正文、汇总状态和 run 进度。单标的失败仍写入一个 `partial` 数据质量的本地诊断项，报告继续处理其他标的。

最终状态规则：全部标的由 AI 成功生成且资料完整时为 `completed`；存在 AI 降级、资料失败或行情不完整时为 `partial`；只有没有任何可诊断标的或无法创建报告骨架时才为 `failed`。已经写入的标的结果在后续标的失败时仍可查看。

## 方法披露与数据边界

AI 成功的标的记录 `ai_analysis`，本地指标记录 `local_function`，二者同时存在时追加 `hybrid_analysis`。本地降级结果不得伪装成 AI 分析。

资料适配器继续通过统一接口提供来源状态。当前仅返回链接的公告、资讯和讨论源仍会被保存为 `link_only`，但不会被描述为已读取新闻。接入真实新闻摘要时，适配器必须限制域名、超时、响应大小和抓取数量，只向 AI 传递标题、发布时间、来源、短摘要和关键事实，不持久化正文。

## API 与前端行为

现有启动、轮询、报告读取接口保持不变。后端逐标的更新 `progress`，前端继续轮询并显示生成进度。报告列表和详情显示单标的降级原因及报告级 AI 状态；不新增浏览器端 AI 请求，也不改变报告归档删除语义。

## 验收用例

后端至少覆盖：

1. 两个持仓产生两次独立 AI 请求，每次输入只包含一个标的，第二个请求在第一个结果落库后开始。
2. 第一个标的 AI 超时或返回错误时，第一个标的保存本地结果，第二个标的仍被处理，run 为 `partial`。
3. AI 成功返回结构化结果时保存 AI 分析、推荐和方法；不支持 JSON 模式的服务商仍可通过普通 JSON 响应完成。
4. 服务返回 4xx、5xx、429、网络错误、超时和非法 JSON 时，报告显示可操作的分类原因，且不包含密钥和完整服务地址。
5. 正文由服务端合成并始终不超过 600 个字符；来源全文不写入数据库。
6. 用户隔离、行情失败、资料源失败、无活动持仓和报告归档删除行为保持现有契约。

前端至少覆盖：

1. 逐标的处理中显示可读进度，部分完成报告仍能打开已落库的标的。
2. AI 成功、本地、超时和不可用状态分别显示，错误原因可见且不误称为 AI 分析。
3. 现有报告切换、来源链接、单条删除和清空归档行为不回归。

## 不在本次范围

- 不增加自动交易、外部通知或浏览器端 API Key。
- 不通过任意网页抓取来补齐新闻；真实新闻摘要必须通过受控、可核验的数据源适配器接入。
- 不让 AI 执行任意服务端代码或直接访问数据库。
