# 韭菜笔记工作区设计

## 目标

在 IronMan 的“韭菜笔记”菜单实现 Batman 的完整笔记工作流：检索、列表、创建、编辑、标签、保存、删除和未保存修改保护。保持 IronMan 的深色工作台风格、统一确认对话框和多用户数据隔离。

## 范围

- 路由 `/notes/leek-notes` 从占位页替换为真实的笔记工作区。
- 左侧占内容宽度约 30%，包含标题或标签筛选、创建入口和按更新时间倒序的笔记列表。
- 右侧占内容宽度约 70%，包含原生 Markdown 编辑区、预览切换、标签编辑、保存和删除操作。
- 保存时从 Markdown 第一行标题提取笔记标题；没有有效标题时保存为“未命名笔记”。
- 新建笔记默认不关联标的，调用现有 notes API 时传递 `instrumentId: null`。
- 使用已有的 `AppConfirmDialog` 处理未保存修改和删除确认，不使用浏览器 alert 或 confirm。

## 编辑体验

不引入 Vditor 或其他编辑器依赖。编辑态使用原生 `textarea`，预览态以受控的 Markdown 渲染展示标题、列表、引用、代码块、粗体、斜体和链接。工具栏提供编辑/预览切换，以及标题、粗体、列表和引用的常用 Markdown 插入操作。

## 数据流

前端复用已有 `POST /api/notes/list`、`create`、`update`、`delete` 接口和 `NoteService`。所有请求携带当前会话令牌；后端继续以 `user_id` 筛选，所以不同用户无法读取、更新或删除彼此笔记。

页面加载后获取笔记列表并选中第一条。笔记保存、删除成功后重新拉取列表。没有笔记时显示只读引导状态。

## 未保存修改保护

页面维护草稿快照与脏状态。选择其他笔记、新建笔记、删除当前笔记、路由离开时，如果有未保存修改，统一对话框提供：保存后继续、放弃修改并继续、取消当前操作。保存失败则留在当前编辑状态。

## 错误与边界

- 空搜索显示空列表，不把它当作错误。
- API 错误通过页面内统一错误提示呈现，并保持当前草稿。
- 标签去重、去空白，每条笔记最多沿用后端的 20 个标签限制。
- 删除请求只在当前笔记有持久化 ID 时可用。

## 验收

- 用户可以创建、保存、修改、删除笔记，并在刷新后看到持久化结果。
- 标题筛选和标签筛选只显示匹配笔记。
- 切换笔记与离开页面时能正确保护未保存修改。
- 删除使用统一确认对话框。
- 后端测试覆盖 CRUD、用户隔离和无效输入；前端测试覆盖列表筛选、草稿保存和确认交互。
